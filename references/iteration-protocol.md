# Iteration protocol

Run this every time new material arrives (a project, a recommendation, a JD, metrics, a correction).

1. **Inventory:** add it to `01-source-index.md`. Note whether it duplicates something already received.
2. **Extract:** add new claims to `02-evidence-ledger.md` with labels.
3. **Compare:** does it strengthen, weaken or contradict an existing pattern or approved statement?
4. **Flag conflicts:** add them to `09-open-questions.md`. Do not pick a side alone.
5. **Propose updates:** say which approved statements could change and why. Proposed is not approved.
6. **Approve:** wait for the person's decision.
7. **Log:** record it in `10-decision-log.md` with the date and the reason.

## Triggers to revisit the brand
- A launch or post-launch metric arrives.
- New testimonials, especially ones that cover an uncovered pillar.
- The target audience changes (new industry, new company type).
- A pattern drops below 3 projects of support, or a new one appears.
- Interview feedback shows a message is not landing.

## Never
- Silently overwrite an approved decision.
- Treat missing material as proof that something did not happen.
- Reintroduce a claim the person has corrected.
