# Evidence rules

## Status labels
| Label | Meaning |
|---|---|
| **V** Verified | Explicitly supported by a source document or artifact |
| **SR** Self-reported | Stated and confirmed by the person, with no document behind it |
| **TP** Third party | A testimonial, review or public record |
| **I** Interpretation | A reasonable conclusion from several facts |
| **H** Hypothesis | A possible strength or positioning to test |
| **P** Projection | A target or forecast. **Never present as a result** |
| **C** Conflicting | Sources disagree. Resolve before use |
| **U** Unknown | Not yet provided |

## Separate these every time
- Personal contribution vs team outcome.
- Discovered vs decided (who made the call?).
- Designed vs built vs launched vs measured.
- Pilot or sample result vs product-wide result.
- Company-level scale vs feature-level usage.
- Inferred user emotion vs observed or reported emotion.

## Contradiction check
Compare across all sources, including materials already sent to employers:
- Numbers (percentages, user counts, revenue, assets).
- Dates and tenure.
- Ownership verbs ("led", "redirected", "owned").
- Launch status.
- Repeated claims that only appear in summaries, never in the full source.

For each conflict, list both versions, their sources, and why it matters. Let the person decide. Lock the decision in the log.

## Calibrated wording
| Instead of | Say |
|---|---|
| "Redirected the project" | "My investigation surfaced the root cause; the team adopted my recommendation" |
| "Increased X by 30%" (projected) | "Targeting a 30% increase" |
| "NPS 66" (from a pilot, reported by a PM) | "A pilot survey reported NPS 66" |
| "Built the design system" (shared) | "Led / contributed to …" with the exact scope |

## Summaries are not sources
Compressed tables and matrices invite errors. Write narrative detail only from the fullest source available.
